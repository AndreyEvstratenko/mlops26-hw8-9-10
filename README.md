# ДЗ 8+9+10: исправленный процесс выпуска и API

Исходные файлы в Downloads и проект ДЗ 6–7 не изменялись. Видео не создавалось.

## Запуск на этом компьютере

1. Откройте папку решения и запустите **run_tests.cmd** двойным щелчком.
   Окно останется открытым. Ожидаются 24 теста этой работы и 24 сохранённых теста ДЗ 6–7, оба прогона `OK`.
2. Для настоящей модели запустите **run_api.cmd**. Оставьте окно открытым.
   API: http://127.0.0.1:8091/docs, `/health`, `/ready`, `/generate`.
3. До окончания загрузки `/ready` возвращает 503. После загрузки и реального прогрева — 200.
   Генерация работает на CPU. Остановка — Ctrl+C в окне сервера.

В Swagger выберите `POST /generate` → Try it out и передайте:

```json
{"prompt":"Метод подтверждения пневмонии: A. Рентгенография грудной клетки; B. Спирометрия. Допустимые метки answer: A, B, REFUSE.","max_new_tokens":16}
```

Это учебная модель с низким качеством из ДЗ 6–7: настоящий ответ API не означает правильный ответ на задачу.
Кандидат честно отклонён за behavioral-кейсы; обслуживается закреплённая исходная baseline.
Зелёные инженерные тесты и отрицательный quality gate — совместимые результаты.

На этом компьютере файлы baseline уже скопированы в `artifacts/baseline`, указатель создан в `runtime`.
`local-config.json` использует существующий Python ДЗ 6–7 только для модели; старое окружение не меняется.
Prefect, тесты и инструменты работают в собственном `.venv` этой папки.

## Если используется распакованный ZIP или другой компьютер

В архив не включены `.venv`, веса, runtime-кеши и временные каталоги. Сначала установите Python 3.12 и uv.

```powershell
.\setup.cmd
.\run_tests.cmd
```

Для самостоятельного окружения с моделью:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -WithModel
.\.venv\Scripts\python.exe prepare_model.py
.\.venv\Scripts\python.exe publish_real.py
.\run_api.cmd
```

`prepare_model.py` скачивает только закреплённую revision Qwen и проверяет каждый файл по сохранённым SHA-256.
Можно использовать уже скачанный snapshot: `prepare_model.py --base-dir "полный путь к snapshot"`.
Для другого Python модели скопируйте `local-config.example.json` в `local-config.json` и исправьте путь.
MLflow и Docker для запуска этой работы не нужны: исходные eval-отчёты и данные включены в `evidence/hw67`.

## Повторение опытов

Из корня проекта, Python собственного окружения:

```powershell
.\.venv\Scripts\python.exe prove_regressions.py
.\.venv\Scripts\python.exe experiments.py
.\.venv\Scripts\python.exe publish_real.py
.\.venv\Scripts\python.exe run_real.py --python "D:\mlops26-hw6-7\hw67-solution\.venv\Scripts\python.exe" --count 8
```

При самостоятельной установке модельных зависимостей последний `--python` можно опустить.
Команды перезаписывают соответствующие отчёты повторного опыта; рабочие стенды получают новые каталоги в `.runs`.
`prove_regressions.py` требует Git-историю, которая включена в ZIP и bundle.

Ручной опыт со STUB в двух терминалах:

```powershell
.\.venv\Scripts\python.exe lab.py --workspace .lab-demo init
.\.venv\Scripts\python.exe service.py --workspace .lab-demo --warmup-seconds 10
# Во втором терминале:
.\.venv\Scripts\python.exe lab.py --workspace .lab-demo run
# До перезапуска API: фактически загружена A. После перезапуска: B.
.\.venv\Scripts\python.exe lab.py --workspace .lab-demo run --manifest manifest-A.json --report report-A.json
# После следующего перезапуска: A.
```

Если `.lab-demo` уже существует, используйте новый путь; `init` ничего не перезаписывает.
`run_api.cmd --stub` также создаёт/использует `.lab-demo` для быстрого просмотра API без модели.

| Новый адаптер | Проверка веса/config, полная оценка `python -m evaluation.cli evaluate` и `gate` в ДЗ 6–7, новый связанный release-report, Prefect, перезапуск API |

Это локальный CI. `ci.example.yml` оставлен как пример, удалённый workflow не запускался и защита merge не заявляется.

## Решения и ограничения

- Публикация рассчитана на одного писателя. Используются атомарные JSON-файлы, write-ahead intent и журнал уникальных release ID. Попытки записываются отдельно.
- ID выпуска учитывает manifest, runtime и полный связанный отчёт. Повтор не создаёт ещё одно событие. Откат к ранее принятой версии снова обновляет указатель, но не дублирует старое событие выпуска; попытка отката сохраняется отдельно.
- Кеш учитывает байты входа, конфигурацию и хеш фактического кода подготовки. Prefect дополнительно учитывает рабочий каталог, поскольку сохранённый результат содержит локальный URI.
- Финальная конфигурация Prefect задаёт SQLite URL с прямыми слешами и временные файлы внутри проекта. Это устранило ошибку открытия БД в локальной среде Windows.
- Если существующий `.prefect` был создан с закрытыми правами другого пользователя, обычный терминал Windows может получить `unable to open database file`. При исправлении восстановлено наследование ACL этого каталога и его файлов; глобальные права Windows не менялись. Новый каталог создаётся до импорта Prefect с обычным наследованием прав родительской папки.
- При системном прокси Windows запрос проверки запуска Prefect к `127.0.0.1` может получить ответ 503 от прокси. `local_network.py` добавляет `127.0.0.1`, `localhost`, `::1` в `NO_PROXY` внутри процесса до запуска Prefect и HTTP-проверок; существующие исключения сохраняются. Настройки прокси Windows не меняются. Дополнительный сервер вручную не требуется.
- `passed=true` в release-report baseline означает разрешение сохранить ранее закреплённую baseline после вычисленного отказа кандидату. Это не PASS кандидату и не заявление о прохождении baseline всех behavioral-кейсов. Код проверяет тип решения и пересчитывает исходный gate при выпуске.
- Старые отчёты не содержат готовый runtime_sha256. Runtime восстановлен по закреплённой revision, коду оценки, params и зафиксированной конфигурации CPU/float32; повторно проверены сырые ответы и метрики. Новая полная оценка не заявляется.
- Веса отклонённого адаптера из MLflow не загружались: MLflow выключен. Его training/evaluation IDs, исходные ответы и отказ сохранены. Обслуживаемая baseline реально загружена и проверена.
- Настройки генерации реальной модели фиксированы: greedy, thinking=false, seed=42, max_new_tokens=16. Изменять лимит на запросе нельзя. Лимит STUB: целое число 1..32.
- Backend обслуживает генерации последовательно под lock, поэтому concurrency=2 добавляет ожидание. CPU, маленькая выборка и один прогон ограничивают выводы.
- Prefill обрабатывает вход; decode строит ответ токен за токеном. KV-cache хранит attention keys/values и растёт с длиной и числом одновременно активных последовательностей. Измеряется полный JSON-ответ, TTFT/ITL не измерялись. Выводов о скорости vLLM/SGLang нет.
