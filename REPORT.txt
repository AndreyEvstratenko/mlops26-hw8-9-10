3. Граф и идентичность
prepare_task -> artifact_task -> gate_task -> publish_task.
Передаются описания/пути/хеши, веса не передаются между задачами.
Подготовка реально декодирует, проверяет и нормализует вход, сохраняет файл.
Ключ: байты входа + tokenizer revision/hash + template + max_length + code_revision
+ хеш фактической реализации. Сохранение результатов Prefect и файловое хранилище
постоянны; task key дополнительно учитывает рабочий каталог из-за локальных URI.
Сеть в текущем офлайн-потоке не используется; retry=0. Невалидные отчёты,
отказ и несовместимые файлы не повторяются автоматически. При будущем сетевом
получении артефактов retry допустим только для временной сетевой ошибки.

Одинаковые первые 8 golden-запросов, одинаковый бюджет, после прогрева.
Сырые попытки, фактические токены, статусы и задержки:

  concurrency=1: n=8, успехов=8, ошибок=0; пакет=17.779 с; req/s=0.450; средняя=2.222 с; максимальная=2.642 с

Ошибок/тайм-аутов в этом прогоне нет; их поля сохранены, код не удаляет неудачи.
При concurrency=2 последовательный backend добавляет очередь; пропускная
способность не выросла. Client latency включает транспорт и ожидание;
generation_seconds — вычисление под lock. В выборке 8+8 нельзя оценивать
устойчивый p95. TTFT/ITL не измерялись: ответ единым JSON, без streaming.
Prefill обрабатывает prompt; decode генерирует токены последовательно.
KV-cache хранит attention keys/values, растёт с длиной и активными запросами.
Этот Transformers-сервис не доказывает производительность SGLang/vLLM.
